第 16 章（补充）数据分层与结构选型方法论

本章不对应原书任何一章,而是这本笔记在教学过程中被反复问到的一个问题:"以前 Redis 用得少,写业务的时候该把哪些数据放数据库、哪些放 Redis、放 Redis 又该选哪种类型,缺一套自己的判断方法论"。原书通篇都在用具体案例(投票系统、购物车、时间线)演示"该用哪个结构",但没有把背后的判断逻辑单独总结成方法论——本章把它显式化。

16.1 第一层判断:这份数据该进数据库还是 Redis

把 Redis 默认当成"可能丢"的存储来设计——即使开了 RDB/AOF 持久化,主从切换、机器故障时仍有丢数据的窗口。围绕这个前提,依次问自己四个问题:

  1. 丢了这份数据,后果有多严重? 会有财务/法律/客诉后果(订单、支付、账户余额、合同、交易流水)→ 必须落 DB,Redis 最多做加速层。丢了顶多体验差一点、能重算或重新拉取(缓存、排行榜、推荐结果、会话)→ 可以放 Redis。
  2. 这份数据是"真相源"还是"衍生数据"? System of Record(用户资料、订单、审计日志)→ DB 存,Redis 顶多缓存一份。Derived data(热度榜、聚合统计、搜索索引)→ 天然适合 Redis,丢了可以从源头重建。Ephemeral(会话、验证码、限流计数、分布式锁)→ 不该进 DB,这类数据生来就有 TTL,Redis 的 EXPIRE 是原生能力,DB 反而要自己写清理逻辑。
  3. 需要的是"速度"还是 Redis 的"原子能力"? 有些场景不是"数据库查询慢所以缓存一下",而是问题本身就该用 Redis 结构建模:高并发原子自增/自减(库存扣减、点赞数)、自动维持排序(排行榜)、集合运算(共同好友、标签匹配)、极低成本去重计数(UV)、分布式锁/限流原语。这类场景第一反应就该是 Redis,不管数据量大不大。
  4. 访问模式是不是"读多写少 + 延迟敏感"? 如果是,且数据集符合二八定律(20% 热数据占 80% 访问量)→ 经典缓存模式:全量在 DB,热数据子集缓存到 Redis。如果需要复杂多条件查询/JOIN/全文检索,Redis 不擅长,该用 DB 或专门的搜索引擎(见第 7、15 章)。

16.2 第二层判断:进了 Redis 该选哪个结构

拿到一份要放 Redis 的数据,按顺序问自己:

一个新手最容易纠结的点——STRING 存 JSON,还是用 HASH?

  • 总是整存整取,不需要单独改某个字段 → STRING 存 JSON,序列化简单。
  • 经常只改一两个字段(购物车只改某个商品数量)→ HASH,避免整体反序列化再序列化。
  • HASH 还有个内存优势:小 HASH 会用紧凑的 listpack 编码存储,比一堆零散的 STRING key 更省内存(细节见第 9 章)。

import uuid, time

def create_session(user_id: str) -> str:
    token = str(uuid.uuid4())
    r.hset(f"session:{token}", mapping={"user_id": user_id, "login_at": time.time()})

    return token

import java.util.Map;
import java.util.UUID;

public static String createSession(String userId) {
    String token = UUID.randomUUID().toString();
    jedis.hset("session:" + token, Map.of(
        "user_id", userId, "login_at", String.valueOf(System.currentTimeMillis() / 1000.0)
    ));
    jedis.expire("session:" + token, 3600);
    return token;
}

public static Map<String, String> getSession(String token) {
    Map<String, String> data = jedis.hgetAll("session:" + token);
    return data.isEmpty() ? null : data;
}

import { randomUUID } from "crypto";

export async function createSession(userId: string): Promise<string> {
  const token = randomUUID();
  await redis.hset(`session:${token}`, { user_id: userId, login_at: Date.now() / 1000 });
  await redis.expire(`session:${token}`, 3600);
  return token;
}

export async function getSession(token: string) {
  const data = await redis.hgetall(`session:${token}`);
  return Object.keys(data).length ? data : null;
}

16.4.3 分布式锁（STRING，SET NX EX + Lua 校验归属再释放）

import uuid

UNLOCK_SCRIPT = """
if redis.call('get', KEYS[1]) == ARGV[1] then
    return redis.call('del', KEYS[1])
end
return 0
"""

def acquire_lock(lock_key: str, ttl: int = 10) -> str | None:
    token = str(uuid.uuid4())
    ok = r.set(lock_key, token, nx=True, ex=ttl)
    return token if ok else None

def release_lock(lock_key: str, token: str) -> bool:
    return bool(r.eval(UNLOCK_SCRIPT, 1, lock_key, token))

import redis.clients.jedis.params.SetParams;
import java.util.Collections;
import java.util.UUID;

static final String UNLOCK_SCRIPT =
    "if redis.call('get', KEYS[1]) == ARGV[1] then return redis.call('del', KEYS[1]) else return 0 end";

public static String acquireLock(String lockKey, int ttlSeconds) {
    String token = UUID.randomUUID().toString();
    String ok = jedis.set(lockKey, token, SetParams.setParams().nx().ex(ttlSeconds));
    return "OK".equals(ok) ? token : null;
}

public static boolean releaseLock(String lockKey, String token) {
    Object result = jedis.eval(UNLOCK_SCRIPT, Collections.singletonList(lockKey), Collections.singletonList(token));
    return Long.valueOf(1).equals(result);
}

import { randomUUID } from "crypto";

const UNLOCK_SCRIPT = `
if redis.call('get', KEYS[1]) == ARGV[1] then
    return redis.call('del', KEYS[1])
end
return 0
`;

export async function acquireLock(lockKey: string, ttl = 10): Promise<string | null> {
  const token = randomUUID();
  const ok = await redis.set(lockKey, token, "EX", ttl, "NX");
  return ok ? token : null;
}

export async function releaseLock(lockKey: string, token: string): Promise<boolean> {
  const result = await redis.eval(UNLOCK_SCRIPT, 1, lockKey, token);
  return result === 1;
}

16.4.4 限流计数器（STRING，固定窗口 INCR；滑动窗口版见第 13 章）

import time

def is_allowed(user_id: str, limit: int = 100, window: int = 60) -> bool:
    key = f"ratelimit:{user_id}:{int(time.time()) // window}"

    if count == 1:

public static boolean isAllowed(String userId, int limit, int window) {
    long bucket = System.currentTimeMillis() / 1000 / window;
    String key = "ratelimit:" + userId + ":" + bucket;
    long count = jedis.incr(key);
    if (count == 1) jedis.expire(key, window);
    return count <= limit;
}

export async function isAllowed(userId: string, limit = 100, window = 60): Promise<boolean> {
  const bucket = Math.floor(Date.now() / 1000 / window);
  const key = `ratelimit:${userId}:${bucket}`;
  const count = await redis.incr(key);
  if (count === 1) await redis.expire(key, window);
  return count <= limit;
}

16.4.6 Feed 时间线（ZSET，发帖时 fan-out 写入粉丝时间线）

def post_and_fanout(user_id: str, post_id: str):
    now = time.time()
    followers = r.zrange(f"followers:{user_id}", 0, -1)
    pipe = r.pipeline()
    for follower_id in followers:
        pipe.zadd(f"timeline:{follower_id}", {post_id: now})
        pipe.zremrangebyrank(f"timeline:{follower_id}", 0, -1001)  # 只留最近1000条
    pipe.execute()

def get_timeline(user_id: str, count: int = 20):
    return r.zrevrange(f"timeline:{user_id}", 0, count - 1)

import java.util.List;

public static void postAndFanout(String userId, String postId) {
    double now = System.currentTimeMillis() / 1000.0;
    List<String> followers = jedis.zrange("followers:" + userId, 0, -1);
    for (String followerId : followers) {
        jedis.zadd("timeline:" + followerId, now, postId);
        jedis.zremrangeByRank("timeline:" + followerId, 0, -1001);
    }
}

public static List<String> getTimeline(String userId, int count) {
    return jedis.zrevrange("timeline:" + userId, 0, count - 1);
}

export async function postAndFanout(userId: string, postId: string) {
  const now = Date.now() / 1000;
  const followers = await redis.zrange(`followers:${userId}`, 0, -1);
  const pipeline = redis.pipeline();
  for (const followerId of followers) {
    pipeline.zadd(`timeline:${followerId}`, now, postId);
    pipeline.zremrangebyrank(`timeline:${followerId}`, 0, -1001);
  }
  await pipeline.exec();
}

export async function getTimeline(userId: string, count = 20) {
  return redis.zrevrange(`timeline:${userId}`, 0, count - 1);
}

16.4.8 消息队列（Stream，带消费组 + ack）

def produce(stream: str, payload: dict):
    r.xadd(stream, payload)

def consume(stream: str, group: str, consumer: str, count: int = 10):
    try:
        r.xgroup_create(stream, group, id="0", mkstream=True)
    except redis.ResponseError:
        pass  # 消费组已存在
    entries = r.xreadgroup(group, consumer, {stream: ">"}, count=count)
    for _, messages in entries or []:
        for msg_id, fields in messages:
            process(fields)
            r.xack(stream, group, msg_id)

import redis.clients.jedis.StreamEntryID;
import redis.clients.jedis.params.XReadGroupParams;
import redis.clients.jedis.resps.StreamEntry;
import java.util.Map;

public static void produce(String stream, Map<String, String> payload) {
    jedis.xadd(stream, StreamEntryID.NEW_ENTRY, payload);
}

public static void consume(String stream, String group, String consumer) {
    var entries = jedis.xreadGroup(group, consumer,
        XReadGroupParams.xReadGroupParams().count(10),
        Map.of(stream, StreamEntryID.UNRECEIVED_ENTRY));
    if (entries == null) return;
    for (var entry : entries) {
        for (StreamEntry e : entry.getValue()) {
            process(e.getFields());
            jedis.xack(stream, group, e.getID());
        }
    }
}

export async function produce(stream: string, payload: Record<string, string>) {
  const fields = Object.entries(payload).flat();
  await redis.xadd(stream, "*", ...fields);
}

export async function consume(stream: string, group: string, consumer: string) {
  try {
    await redis.xgroup("CREATE", stream, group, "0", "MKSTREAM");
  } catch {
    // 消费组已存在
  }
  const res = await redis.xreadgroup("GROUP", group, consumer, "COUNT", 10, "STREAMS", stream, ">");
  if (!res) return;
  for (const [, messages] of res as any) {
    for (const [id, fields] of messages) {
      process(fields);
      await redis.xack(stream, group, id);
    }
  }
}

16.4.11 库存扣减（STRING，Lua 保证"检查够不够 + 扣减"原子）

DEDUCT_SCRIPT = """
local stock = tonumber(redis.call('get', KEYS[1]) or '0')
if stock < tonumber(ARGV[1]) then
    return -1
end
return redis.call('decrby', KEYS[1], ARGV[1])
"""

def deduct_stock(sku: str, qty: int) -> int:
    return r.eval(DEDUCT_SCRIPT, 1, f"stock:{sku}", qty)  # -1 表示库存不足

import java.util.Collections;

static final String DEDUCT_SCRIPT =
    "local stock = tonumber(redis.call('get', KEYS[1]) or '0') " +

    "return redis.call('decrby', KEYS[1], ARGV[1])";

public static long deductStock(String sku, int qty) {
    Object result = jedis.eval(DEDUCT_SCRIPT,

        Collections.singletonList(String.valueOf(qty)));
    return (Long) result;
}

const DEDUCT_SCRIPT = `
local stock = tonumber(redis.call('get', KEYS[1]) or '0')
if stock < tonumber(ARGV[1]) then
    return -1
end
return redis.call('decrby', KEYS[1], ARGV[1])
`;

  return redis.eval(DEDUCT_SCRIPT, 1, `stock:${sku}`, qty) as Promise<number>;

16.4.12 验证码/一次性 token（STRING + EXPIRE，验证后立即删除防重放）

import random

def send_code(phone: str) -> str:
    code = f"{random.randint(0, 999999):06d}"
    r.set(f"otp:{phone}", code, ex=300)
    return code

def verify_code(phone: str, code: str) -> bool:
    key = f"otp:{phone}"
    saved = r.get(key)
    if saved == code:
        r.delete(key)
        return True
    return False

import java.util.concurrent.ThreadLocalRandom;

public static String sendCode(String phone) {
    String code = String.format("%06d", ThreadLocalRandom.current().nextInt(1_000_000));
    jedis.setex("otp:" + phone, 300, code);
    return code;
}

public static boolean verifyCode(String phone, String code) {
    String key = "otp:" + phone;
    String saved = jedis.get(key);
    if (code.equals(saved)) {
        jedis.del(key);
        return true;
    }
    return false;
}

export async function sendCode(phone: string): Promise<string> {
  const code = String(Math.floor(Math.random() * 1_000_000)).padStart(6, "0");
  await redis.set(`otp:${phone}`, code, "EX", 300);
  return code;
}

export async function verifyCode(phone: string, code: string): Promise<boolean> {
  const key = `otp:${phone}`;
  const saved = await redis.get(key);
  if (saved === code) {
    await redis.del(key);
    return true;
  }
  return false;
}

16.5 常见反模式

  • 把 Redis 当成唯一存储去存不能丢的数据——没有 DB 兜底的"真相源",出故障就是真丢。
  • 不管什么数据都用 STRING 存整个 JSON——该用 HASH/ZSET 建模的结构化数据硬塞进字符串,应用层要反复整体序列化/反序列化,也丧失了 Redis 原生的原子操作能力。
  • 单个 key 存超大 value(几十 MB 的大列表/大 JSON)——读写会阻塞,也容易造成内存碎片,详见第 9 章。
  • 缓存了但没设计失效策略——导致缓存和数据库不一致,或引发缓存穿透/击穿/雪崩,详见第 2 章页面缓存部分。
本章小结

这套方法论的核心是两层过滤:第一层判断"这份数据能不能丢、是不是真相源",决定它该不该进 Redis;第二层判断"这是一个值还是一组值、要不要排序、要不要原子运算",决定选哪个结构。原书用一个个具体案例(投票系统、购物车、时间线)教会你怎么做,这一章把背后反复出现的判断逻辑显式地总结出来——以后遇到新的业务需求,可以直接对照本章的两张决策图和速查表,而不必凭直觉猜。

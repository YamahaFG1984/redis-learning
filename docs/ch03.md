# 第 3 章 Redis 命令大全

> 对应原书第 3 章 "Commands in Redis"。原书说这一章覆盖了"日常使用中 95% 以上"的 Redis 命令；这里在保留原书结构的基础上，把每个命令族更新到当前 Redis 版本，并标注哪些是这些年新增的能力。

原书写作时 Windows 上能下载到的编译版还是 Redis 2.4，书中大量用到 2.6 的新特性，专门开了一个提示框："2.4 和 2.6 的区别"：Lua 脚本、毫秒级过期（PTTL/PEXPIRE/PEXPIREAT）、位运算（BITOP/BITCOUNT）、以及 RPUSH/LPUSH/SADD/SREM/HDEL/ZADD/ZREM 从"只能传一个值"变成"能传多个值"。这个提示放到今天格外有历史感——**现在 Redis 的版本节奏是每年一个大版本，2.x 时代那种"这个命令还不支持多参数"的问题早已不存在**，但它提醒我们：命令的能力边界是随版本演进的，写生产代码前查一下"该命令从哪个版本开始支持这个选项"是好习惯。

## 3.1 字符串（STRING）

| 命令 | 作用 |
|---|---|
| INCR / DECR | ±1 |
| INCRBY / DECRBY | ±N（整数） |
| INCRBYFLOAT | ±N（浮点，2.6+） |
| APPEND | 追加 |
| GETRANGE | 取子串（原名 SUBSTR，2.6 后统一叫 GETRANGE） |
| SETRANGE | 从偏移量写子串（不够长会用 `\0` 补齐） |
| GETBIT / SETBIT | 位读写 |
| BITCOUNT | 统计 1 的个数 |
| BITOP | AND/OR/XOR/NOT |

**现代新增**（原书完全没有）：

- `SET key value EX seconds NX/XX GET` —— Redis 2.6.12 起 `SET` 自带了 `SETNX`/`SETEX` 的能力，现在几乎不需要单独调用 `SETNX`/`SETEX`/`PSETEX` 了，一律用 `SET ... EX ... NX` 就够。
- `GETDEL`（6.2+）：取值并删除，一步到位。
- `GETEX`（6.2+）：取值的同时刷新/清除 TTL。
- `COPY`（6.2+）：原子复制一个 key。
- `OBJECT FREQ`/`OBJECT IDLETIME`：配合 LFU/LRU 淘汰策略查看访问频率/空闲时间。
- `BITFIELD`（3.2+）：在一个字符串里打包多个任意位宽的整数字段，一次调用完成多个位域的读写——这是对原书第 9 章"手动拼位"技巧的官方增强版。

## 3.2 列表（LIST）

| 命令 | 作用 |
|---|---|
| RPUSH / LPUSH | 右/左端插入 |
| RPOP / LPOP | 右/左端弹出 |
| LINDEX | 按下标取值 |
| LRANGE | 取一段 |
| LTRIM | 裁剪保留一段 |
| BLPOP / BRPOP | 阻塞弹出 |
| RPOPLPUSH / BRPOPLPUSH | 弹出并推入另一个列表 |

**现代新增/变化**：

- `LPOP`/`RPOP` 从 6.2 起支持一次弹出 `count` 个元素（`LPOP key count`），不用再循环调用。
- `LMPOP`/`BLMPOP`（7.0+）：一次从多个列表中弹出，替代了原书里"依次尝试多个队列做优先级"的部分场景。
- `LMOVE`/`BLMOVE`（6.2+）：`RPOPLPUSH`/`BRPOPLPUSH` 的正式继任者，语义相同但命名更清晰（可以是同一个 LIST 内部转移）。**`RPOPLPUSH` 现已标记为 deprecated**，新代码应该用 `LMOVE`。
- `LPOS`（6.0.6+）：按值查找元素位置（原来只能自己 `LRANGE` 全量扫描）。

原书这里有个练习题："用 LIST 替代 ZSET 做最近访问记录以节省内存"——这个思路今天依然成立：ZSET 每个成员要存分数（8 字节 double）+ 跳表指针开销，而 LIST（尤其是 listpack 编码下）纯粹是"顺序 + 值"，在只需要"最近 N 条、不需要按分数查询"的场景下更省内存。

## 3.3 集合（SET）

| 命令 | 作用 |
|---|---|
| SADD / SREM | 增/删 |
| SISMEMBER / SMISMEMBER（6.2+，批量判断） | 成员判断 |
| SCARD | 元素个数 |
| SMEMBERS | 取全部（**大集合慎用**，原书明确警告过） |
| SRANDMEMBER / SPOP | 随机取/随机弹出 |
| SMOVE | 集合间移动元素 |
| SINTER/SUNION/SDIFF（+STORE 变体） | 交/并/差 |

**现代补充**：`SSCAN` 配合游标做增量遍历大 SET，避免 `SMEMBERS` 卡住整个 Redis（`SCAN` 系列命令——`SCAN`/`HSCAN`/`SSCAN`/`ZSCAN`——本身也是 2013 年之后（Redis 2.8）才引入的，原书完全没有涉及，这是这些年最重要的运维安全补丁之一：**不要在生产环境用 `KEYS *`，用 `SCAN` 游标遍历**）。

原书指出一个当时的 client 库 bug：Python 客户端的 `srem()` 返回布尔值而不是 Redis 实际返回的删除个数——这是**客户端库的问题，不是 Redis 命令本身的问题**，现代 redis-py/Jedis/ioredis 都已经如实返回整数。

## 3.4 哈希（HASH）

| 命令 | 作用 |
|---|---|
| HSET / HMSET（已废弃，用 HSET） | 写入 |
| HGET / HMGET | 读取 |
| HDEL | 删除字段 |
| HGETALL / HKEYS / HVALS | 取全部/键/值 |
| HINCRBY / HINCRBYFLOAT | 字段自增 |
| HLEN / HEXISTS | 长度/是否存在 |

**现代新增（Redis 7.4，2024）—— HASH 字段级 TTL**：`HEXPIRE`/`HPEXPIRE`/`HEXPIREAT`/`HPERSIST`/`HTTL`/`HGETEX`/`HGETDEL`。这是这些年 HASH 命令族最大的补强：以前 HASH 只能整体设置过期（`EXPIRE` 作用在整个 key 上），现在可以对单个字段设置独立 TTL，原书第 2、5 章手写的"清理循环"很多场景下可以直接用这组命令替代。

## 3.5 有序集合（ZSET）

| 命令 | 作用 |
|---|---|
| ZADD / ZREM | 增/删 |
| ZSCORE / ZMSCORE（6.2+批量） | 查分数 |
| ZRANK / ZREVRANK | 查排名 |
| ZRANGE / ZREVRANGE | 按排名取一段 |
| ZRANGEBYSCORE / ZREVRANGEBYSCORE | 按分数取一段 |
| ZINCRBY | 分数自增 |
| ZCARD / ZCOUNT | 数量/按分数计数 |
| ZREMRANGEBYRANK / ZREMRANGEBYSCORE | 按排名/分数批量删除 |
| ZINTERSTORE / ZUNIONSTORE | 交/并（可加权重、聚合方式） |

**现代新增**：

- `ZRANGE` 从 6.2 起被"合并"了——`ZRANGEBYSCORE`/`ZREVRANGEBYSCORE`/`ZRANGEBYLEX` 等的功能都可以通过 `ZRANGE key min max BYSCORE|BYLEX [REV] [LIMIT]` 一个命令表达，官方建议新代码优先用统一后的 `ZRANGE`。
- `ZRANGESTORE`（6.2+）：把 `ZRANGE` 的结果直接存成一个新 ZSET，不需要客户端读回来再写回去——第 10 章原书手写的"先查询、再交集/并集合并分片结果"这类模式，很多场景可以用它简化。
- `ZDIFF`/`ZDIFFSTORE`（6.2+）：ZSET 版本的差集，原书写作时压根没有这个命令。
- `ZADD` 支持 `GT`/`LT`/`NX`/`XX` 选项（3.0.2+/6.2+ 逐步补齐）：比如"只有新分数更高才更新"（`GT`），原书第 1 章的排行榜类场景现在可以少写一次 `ZSCORE` 判断。
- `ZMPOP`/`BZMPOP`（7.0+）：从多个 ZSET 弹出最高/最低分成员。

## 3.6 发布/订阅（Pub/Sub）

原书列出 5 个命令：`SUBSCRIBE`/`UNSUBSCRIBE`/`PUBLISH`/`PSUBSCRIBE`/`PUNSUBSCRIBE`，并且花了很大篇幅讲**为什么全书几乎不用 pub/sub**：

1. **可靠性问题**：旧版本 Redis 里，一个消费慢的订阅者会导致 Redis 给它攒的发送缓冲区无限增长，可能拖垮甚至压根让 Redis 被 OS kill 掉；后来的版本靠 `client-output-buffer-limit pubsub` 配置项来主动断开慢订阅者（这一点在现代 Redis 里没有变化，依然要留意这个配置）。
2. **消息不持久**：订阅者一旦断线，断线期间发布的消息全部丢失，没有重放能力。

这两个问题在 2013 年只能靠"干脆不用 pub/sub，自己拿 LIST/ZSET 搭建可靠队列"来解决（第 6 章的内容）。**现代 Redis 有了正式答案：Redis Stream（`XADD`/`XREAD`/`XREADGROUP`/`XACK`，5.0+）**。Stream 原生支持：

- 消息持久化在一个真正的日志结构里，订阅者断线重连后可以从上次的位置继续读（消费组 `XREADGROUP` + `XACK` 机制）。
- 消费组（Consumer Group）语义，多个 worker 分摊消费同一个流，类似 Kafka。
- `XPENDING`/`XCLAIM` 处理"消费者拿到消息但没确认"的情况。

如果你今天要在 Redis 里做消息队列/事件总线，**优先考虑 Stream，而不是重新发明原书第 6 章那一整套 LIST+ZSET 手工方案**——但理解那套手工方案的设计思路仍然很有价值，因为 Stream 内部机制本质上是同一类问题的官方实现。

## 3.7 其他命令

### SORT

`SORT` 可以对 LIST/SET/ZSET 排序，还能用 `BY`/`GET` 语法引用外部 HASH 的字段（`BY weight_*->field`），这是 Redis 里少见的"跨结构关联查询"能力，很像 SQL 的 `ORDER BY` 引用其他表。第 7 章会把它和 SET 运算结合起来做搜索。

**现代提醒**：`SORT` 的 `BY`/`GET` 外部引用模式在 **Redis Cluster 下不可用**（因为引用的 key 可能落在别的分片上），原书 2013 年写作时 Redis Cluster 还没发布，完全没提到这个限制，实际生产中如果上了 Cluster，这类 SORT 用法需要重新设计。

### 基础事务：WATCH/MULTI/EXEC

本章只讲最简单的 `MULTI`/`EXEC`（不带 WATCH），完整的乐观锁用法留到第 4 章。核心概念："一次不被打断的批量执行"，**不是关系型数据库那种可以部分回滚的事务**——一旦 `EXEC`，所有排队的命令都会顺序执行完，中途不会被其他客户端的命令插入，但也不支持"执行到一半发现问题就回滚"。

现代 Redis 事务模型没有变化，但今天更常见的替代方案是：

- **Lua 脚本/Redis Functions**：单个脚本本身就是原子的，比 MULTI/EXEC + WATCH 更简洁（第 11 章详解）。
- 如果只是要保证"读后写"不被并发覆盖，现代客户端库通常直接封装好了 `WATCH` 重试模式（如 redis-py 的 `Pipeline` 支持 `watch()` + 回调自动重试）。

### 过期（Expiration）

| 命令 | 作用 |
|---|---|
| EXPIRE / PEXPIRE | 秒/毫秒后过期 |
| EXPIREAT / PEXPIREAT | 指定时间戳过期 |
| PERSIST | 取消过期 |
| TTL / PTTL | 查剩余时间 |

原书强调一个至今没变的限制：**容器类型（LIST/SET/HASH/ZSET）只能整体过期，不能给里面的单个元素设置 TTL**——这也是原书里大量出现"用 ZSET 存时间戳 + 手写清理循环"模式的根本原因。

**这一点在 2024 年被部分打破**：Redis 7.4 引入的 `HEXPIRE` 系列命令让 HASH 的**单个字段**可以有自己的 TTL 了（前面 3.4 节提到过）。这是十年来对这个长期限制最实质的一次补强，但请注意——**目前只有 HASH 支持字段级 TTL，LIST/SET/ZSET 依然是整体过期**。

Redis 7.0 起 `EXPIRE`/`PEXPIRE`/`EXPIREAT` 还新增了 `NX`/`XX`/`GT`/`LT` 选项（只在没有 TTL 时设置 / 只在已有 TTL 时设置 / 只在新 TTL 更长时设置 / 只在新 TTL 更短时设置），原书完全没有涉及。

## 3.8 本章小结

原书统计这一章覆盖了 70+ 个命令，官方文档 `redis.io/commands` 现在收录的命令数量已经远超这个数字（加上 Stream、Geo、HyperLogLog、Bitfield、JSON、Search 等模块命令，总数是当年的好几倍）。原书作者坦诚地说"这本书给出的不总是最优答案"，多个练习题就是让读者回头改进第 1、2 章的示例代码——这个态度本身值得学习：**先写能跑的版本，再迭代到更好的版本**，不要一开始就追求完美设计。
